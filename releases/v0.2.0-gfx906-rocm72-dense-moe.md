# v0.2.0-gfx906-rocm72-dense-moe - ROCm7.2 Dense/MoE GFX906 Active Contracts

This is the published v0.2.0 release boundary for the ROCm7.2 Dense/MoE
GFX906 active-contract milestone.

v0.1.0 remains the earlier Qwen3.6/GFX906/MI50 TP4 published release baseline.
GitHub Releases are canonical for published release claim boundaries. Docker
Hub remains an evergreen artifact distribution channel and should not be treated
as the latest benchmark announcement.

[qwen36-gfx906/README.md](../qwen36-gfx906/README.md) remains the canonical
deployment and reproducibility package for this release.

## Scope

- Dense 27B is gate-cleared for the recorded active-contract TP8 full-BAR/P2P-on
  lane.
- Qwen3.6 35B-A3B MoE TP8 is the current strict-valid full-BAR/P2P-on MoE bar.
- Qwen3.6 35B-A3B MoE TP4 has capped fixed-token results, but it is not a
  strict-valid publication claim because the uncapped strict prompt did not
  stop / invalid/runaway.
- The same ROCm7.2 image covers the active dense and MoE contracts with
  model-specific environment settings and overlays.
- These are benchmark and reproducibility artifacts, not general workload
  guarantees.

## Platform Remediation

The full-BAR/P2P-on lane required platform remediation:

- Official AMD VBIOS standardization was required.
- No modified BIOS images were used.
- `amdgpu` source patching was required for the full-BAR/P2P-on lane.
- This is not a user instruction to flash cards.
