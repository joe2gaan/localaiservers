## Active Contracts

Verified portable performance at `MAX_MODEL_LEN=131072` with eight pre-measure
warmups.

### Dense 27B TP8 Full-BAR/P2P-On

- Profile: `dense27b_tp8_fullbar_p2pon`
- Host: `.20`
- Strict backend TPS: `69.514`
- `c1_2000` backend TPS: `70.347`
- `c1_10000` backend TPS: `66.069`
- Strict gate: valid
- ai-info 10K gate: cleared for the recorded active-contract lane

### Qwen3.6 35B-A3B MoE TP8 Full-BAR/P2P-On

- Profile: `moe35b_tp8_fullbar_p2pon`
- Host: `.30`
- Strict backend TPS: `94.907`
- `c1_2000` backend TPS: `97.028`
- `c1_10000` backend TPS: `91.290`
- Strict gate: valid
- Publication status: strict-valid MoE publication bar. The fixed-token values
  above are release-time measured points, not guaranteed repeatability floors.

### Qwen3.6 35B-A3B MoE TP4 Full-BAR/P2P-On

- Profile: `moe35b_tp4_fullbar_p2pon`
- v0.2.0 fixed-token release-time result:
  - `c1_2000` backend TPS: `116.146`
  - `c1_10000` backend TPS: `109.283`
- Initial release-time caveat:
  - One uncapped strict prompt was classified as invalid/runaway, so TP4 was
    initially documented as capped fixed-token only.

#### Correction / Post-Release Repeatability Validation

A follow-up repeatability study using the same published v0.2.0 image and
native `moe35b_tp4_fullbar_p2pon` release profile found that the TP4 strict
runaway did not reproduce.

- TP4 strict repeats: `6/6` passed across `.20` and `.30`
- All repeats finished with `finish_reason=stop`.
- All repeats had `qwen_gate_valid=true`.
- Strict backend TPS range: `113.196` to `115.995`.
- Fixed sanity:
  - `.20`: c1_2000 `116.787`, c1_10000 `109.622`
  - `.30`: c1_2000 `115.770`, c1_10000 `108.950`

No code, Docker image, model package, release tag, or runtime artifact changed.
This correction updates the release notes to reflect the post-v0.2 repeatability
evidence.

## 2026-06-22 Public Deploy Reproduction Check

A follow-up deployment check used the published image and current public
deployment package with the same normal benchmark ladder. It confirmed the
dense gate and TP4 corrected band, and it reproduced the MoE TP8 strict-valid
bar on `.20`. The MoE TP8 fixed-token values repeated lower than the original
release-time high point.

| Profile | Host | Strict backend TPS | `c1_2000` backend TPS | `c1_10000` backend TPS | Interpretation |
| --- | --- | ---: | ---: | ---: | --- |
| `dense27b_tp8_fullbar_p2pon` | `.20` | `68.962` | `69.914` | `65.645` | dense ai-info 10K gate confirmed |
| `moe35b_tp8_fullbar_p2pon` | `.20` | `94.637` | `94.742` | `89.489` | strict-valid bar reproduced; fixed-token tiers lower |
| `moe35b_tp8_fullbar_p2pon` | `.30` | `91.773` | `93.476` | `88.935` | lower fixed-token repeat on this host/run |
| `moe35b_tp4_fullbar_p2pon` | `.20` | `114.725` | `116.429` | `109.531` | TP4 corrected strict/fixed band confirmed |
| `moe35b_tp4_fullbar_p2pon` | `.30` | `114.289` | `115.966` | `109.131` | TP4 corrected strict/fixed band confirmed |

This repeat check did not change code, Docker image, model package, release tag,
or runtime artifacts. It narrows the public reproduction claim: Dense TP8
clears the 10K gate, MoE TP4 repeats in the corrected strict/fixed band, and
MoE TP8 strict validity repeats, while MoE TP8 fixed-token throughput is
output-path and run-instance sensitive.
