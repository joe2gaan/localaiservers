# v0.2.1-gfx906-rocm72-dense-moe-repro - ROCm7.2 Dense/MoE Reproduction Package

## Release Boundary

This is a reproduction-package release for the published
`v0.2.0-gfx906-rocm72-dense-moe` ROCm7.2 Dense/MoE milestone.

v0.2.1 does not change the Docker image, Docker Hub manifest digest, model
package, runtime artifact, benchmark values, or v0.2.0 benchmark release
boundary. It packages the corrected public reproduction docs/scripts and the
2026-06-22 reproduction report in a named checkout that is easier to use than a
raw commit SHA.

GitHub Releases remain canonical for published release claim boundaries. Docker
Hub remains an evergreen artifact distribution channel and should not be
treated as the latest benchmark announcement.

## Reproduce The Results

Clone the reproduction package:

```bash
git clone --depth 1 --branch v0.2.1-gfx906-rocm72-dense-moe-repro https://github.com/joe2gaan/localaiservers.git
cd localaiservers/qwen36-gfx906
```

Choose one profile:

```bash
# Dense 27B TP8 full-BAR/P2P-on
export QWEN36_PROFILE=dense27b_tp8_fullbar_p2pon

# MoE TP8 full-BAR/P2P-on
# export QWEN36_PROFILE=moe35b_tp8_fullbar_p2pon

# MoE TP4 full-BAR/P2P-on
# export QWEN36_PROFILE=moe35b_tp4_fullbar_p2pon
```

Deploy the published v0.2.0 image:

```bash
DEPLOY_IMAGE=joe2gaan/localaiservers:qwen36-gfx906-rocm72-dense-moe-runtime-archive-0a2dbd6b7f0b \
DOCKER_ISOLATED_DAEMON_ENABLED=0 \
HF_HUB_DISABLE_XET=1 \
USE_PREBUILT_IMAGE=1 \
PREBUILT_IMAGE_PULL=1 \
AUTO_STAGE_MODEL=1 \
./deploy.sh
```

After readiness:

```bash
./smoke-test.sh
./run_v02_profile_benchmark.sh
```

The v0.2 profile benchmark runs the release scorer path: eight 2000-token
pre-measure warmups, the uncapped `c1_128` strict prompt, `c1_2000`, and
`c1_10000` through the bundled begin-think proxy.

## Published v0.2.0 Values

| Profile | Strict backend TPS | `c1_2000` backend TPS | `c1_10000` backend TPS | Status |
| --- | ---: | ---: | ---: | --- |
| Dense 27B TP8 full-BAR/P2P-on | `69.514` | `70.347` | `66.069` | strict-valid; ai-info 10K gate cleared |
| Qwen3.6 35B-A3B MoE TP8 full-BAR/P2P-on | `94.907` | `97.028` | `91.290` | strict-valid MoE publication bar; fixed-token values are release-time measured points |
| Qwen3.6 35B-A3B MoE TP4 full-BAR/P2P-on | corrected post-v0.2 range `113.196`-`115.995` | `116.146` | `109.283` | TP4 strict runaway did not reproduce in follow-up |

`91.290` is the MoE TP8 `c1_10000` backend TPS, not the strict TPS. MoE TP4
`109.283` is a release-time fixed-token `c1_10000` value.

## 2026-06-22 Public Deploy Reproduction Check

The reproduction-package path was validated with the published image and normal
benchmark ladder:

| Profile | Host | Strict backend TPS | `c1_2000` backend TPS | `c1_10000` backend TPS | Interpretation |
| --- | --- | ---: | ---: | ---: | --- |
| `dense27b_tp8_fullbar_p2pon` | `.20` | `68.962` | `69.914` | `65.645` | dense ai-info 10K gate confirmed |
| `moe35b_tp8_fullbar_p2pon` | `.20` | `94.637` | `94.742` | `89.489` | strict-valid bar reproduced; fixed-token tiers lower |
| `moe35b_tp8_fullbar_p2pon` | `.30` | `91.773` | `93.476` | `88.935` | lower fixed-token repeat on this host/run |
| `moe35b_tp4_fullbar_p2pon` | `.20` | `114.725` | `116.429` | `109.531` | TP4 corrected strict/fixed band confirmed |
| `moe35b_tp4_fullbar_p2pon` | `.30` | `114.289` | `115.966` | `109.131` | TP4 corrected strict/fixed band confirmed |

This repeat check confirmed the Dense TP8 10K gate, confirmed the corrected
MoE TP4 strict/fixed-token band, and reproduced the MoE TP8 strict-valid bar on
`.20`. MoE TP8 fixed-token throughput repeated lower than the v0.2.0
release-time high point, so those fixed-token values should be read as measured
release points rather than repeatability floors.
