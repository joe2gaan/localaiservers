# Program Boundaries

LocalAIServers maintains public documentation and open-source infrastructure notes as
charitable public education work. This file separates charitable donations from any
non-donation program payments or logistics that may exist outside this public
repository.

## Required Boundary Statement

Charitable donations support public documentation, open-source maintenance, QC
methodology, benchmark reporting, and community AI research access. Program payments for
hardware verification, pass-through costs, or fulfillment are separate from donations.

## Charitable Donations

Charitable donations support public-benefit work such as:

- Reproducible local AI deployment notes.
- GFX906 / MI50-class hardware documentation.
- Benchmark reporting templates and review.
- Hardware verification methodology.
- Open-source maintenance.
- Public education around locally hosted AI servers.

Donations must not be described as payment for hardware, service access, private
assistance, fulfillment, or program participation.

## Open-Source and Public Documentation Work

Open-source and public documentation work should be available for public review.
Improvements should be committed through normal repository workflows and should avoid
private operational details.

Examples include:

- README improvements.
- Runtime reproduction notes.
- Smoke-test documentation.
- Benchmark issue templates.
- QC methodology documentation.
- Grant-facing public summaries.

## Hardware Verification and Program Payments

Hardware verification/program payments, if any, are separate from charitable donations.
They may relate to verification work, pass-through costs, fulfillment, or shipping
logistics, but they must not be represented as charitable donations unless reviewed and
disclosed appropriately.

This repository should not include payment collection details for those activities.

## Pass-Through Costs

Pass-through costs are not charitable donations by default. Public wording should avoid
implying that a pass-through cost is deductible, charitable, or connected to donor
benefits unless reviewed by qualified advisors.

## Fulfillment and Shipping Logistics

Fulfillment and shipping logistics are operational matters and should not be published
in this repository. Do not commit labels, participant lists, payment records, shipping
records, banking details, supplier records, or private logistics notes.

## No Private Benefit for Donors

Donations do not provide hardware, preferential treatment, discounts, procurement
access, program participation, or other private benefits. Any goods or services
connected to a non-donation program must be clearly separated from charitable donations
and specifically disclosed.

## Public Repository Rule

Assume donors, grant reviewers, technical contributors, and community members will read
every changed file. If a file contains private operations data or payment details, it
does not belong in the public repository.
